## Lecture 12

- Trade-off:
  - Inter-operator: less communication
  - Intra-operator: less idle time

- MFU = #FLOPs / t / peak FLOPS
  - MFU: Model Flops Utilization
  - #FLOPS: Program's total flops
  - t: Time to finish the program
  - peak FLOPS: GPU constant
  - HFU: Hardware Flops Utilization

- Communication:
  - P2P
  - Collective
    - Broadcast / Reduce
    - Scatter / Gather
    - Allgather / Reduce-scatter
  - Collective can be assembled using many P2P
  - Collective is highly optimized ("xCCL" libraries)

- $\alpha\beta$ model
  - $\alpha + n\beta$, $\beta = \frac{1}{B}$
  - $n$: message size, $B$: bandwidth
  - Small message: $\alpha$ dominates
    - General principles: Low latency
    - "Minimal-spanning tree algorithm"
  - Large message: $n\beta$ dominates
    - General principles: High bandwidth
    - How many rounds of communication does not matter
    - "Ring algorithm"
      - Reduce = Reduce-scatter + Gather
      - Allreduce = Reduce-scatter + Allgather
      - Broadcast = Scatter + Allgather

- Asynchronous pipeline schedules
  - Pros: No pipeline bubbles

  - AMPNet: Fully asynchronous. No bubble. Hard to generalize to large datasets

  - Pipedream-2BW: Only store two versions
